**What's in the PR:**
- **English CV:** `data/cv.en.md` is a faithful translation of `data/cv.md`: same sections, same order, same facts and dates, nothing added. The PR says the user must review it before publication. `data/cv.md` is untouched.
- **Section check:** `web/scripts/sync-cv.mjs` turns both files into `web/src/lib/cv.json`. It runs in `npm run build` and as a `--check` step in CI. It fails if the two languages differ in section count, section order or paragraph count.
- **Contact section dropped from the page:** the markdown's last section ("Contact", which just points to the site) is left out. The real contact is shown in the page header instead. That's why the page shows 11 sections, not 12.
- **Pages `/cv/` and `/en/cv/`:**
  - the CV as HTML
  - `job@stevelang.net` and LinkedIn with `rel="me noopener"`
  - a "Télécharger le CV (PDF)" / "Download the resume (PDF)" button
  - a link to the demo
  - a print stylesheet that hides the navigation and buttons
- **Navigation:** "CV" is a new tab in both languages, and LinkedIn is added to the home page header.
- **PDF generation, and why:** it's a separate step, `npm run pdf` (`web/scripts/cv-pdf.mjs`), so `npm run build` still works on a machine without a browser.
  - It serves `web/out` locally and prints the two pages with Playwright's Chromium.
  - In CI's `web` job, it installs Chromium the same way the e2e job does, runs `npm run pdf`, then checks both files exist, are non-empty and start with `%PDF-`. All of this happens before the `web-out` artifact that deploy syncs to S3 is uploaded.
  - The e2e job also runs `npm run pdf` so the tests can download the files.
  - The page always links to the PDF. Only on a local build that skips `npm run pdf` would that link 404.
- **S3 content type:** `aws s3 sync` sets `application/pdf` from the `.pdf` extension. I added a check to the post-deploy smoke test that both PDFs come back with that content type.
- **Keeping the English CV out of the RAG index:**
  - Ingestion only reads `cv_path`, which is `data/cv.md` in the defaults and every settings file.
  - I added `data/cv.en.md` to `.dockerignore`, so the Dockerfile's `COPY data` no longer puts it in the API image.
  - Two new tests in `tests/test_ingest.py` check the settings and `.dockerignore`, and that ingestion reads only `data/cv.md` even when `cv.en.md` sits next to it. A real ingest still produced 12 passages, the same as before.
- **Other tests:** Vitest for FR/EN parity (including identical years per section) and for the page view; node tests for the parser and the PDF metadata step; e2e with axe on both pages, desktop and mobile; `/cv/` and `/en/cv/` added to both Lighthouse configs. `architecture.json` and `xops.json` were regenerated because `ci.yml` changed.
