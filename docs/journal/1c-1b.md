### Findings

**Critical: none.**

**Important**

1. **The per-request trace flush is not bounded to 2 s.** `src/ask_my_cv/telemetry.py:275-292, 316-317`
   - OTLPSpanExporter's default per-export timeout is 10 s, with retries inside that window.
   - In SDK 1.45, `BatchProcessor.force_flush` ignores `timeout_millis` (`_shared_internal/__init__.py:232`, TODO #4568).
   - The two processors are flushed one after the other.
   - Measured with an endpoint returning 503: `force_flush(2000)` took **3.4 s per exporter** (6.8 s for two). A black-holed endpoint can take up to about 10 s each.
   - `app.py:115` waits for the flush before closing the stream, so the SSE stream and the Lambda invocation stay open that long.
   - Fix: `EXPORT_TIMEOUT_S = 2.0` and pass `timeout=EXPORT_TIMEOUT_S` to both exporters.
   - Test:
     ```python
     def test_exporters_have_a_short_timeout(monkeypatch):
         monkeypatch.setenv("LANGFUSE_PUBLIC_KEY", "pk"); monkeypatch.setenv("LANGFUSE_SECRET_KEY", "sk")
         for name in ("cloudwatch", "langfuse"):
             exporter = exporter_for(name, settings(tracing=[name]))
             assert exporter._client._timeout &lt;= 2.0
     ```

2. **DynamoDB calls can block the event loop for about 90 s.** `container.py:16-26`
