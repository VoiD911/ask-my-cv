**Per finding:**
1. **Pure-digit tokens:** fixed. A token must contain at least one letter a–f to get the "hors historique publié" tag, so pure-digit tokens are never tagged. On top of what you asked, a pure-digit prefix of an old SHA is only translated when a git keyword comes right before it, so a timestamp or counter isn't rewritten by accident. Tests cover `- 1737532800 …`, `commit 1737532800`, `port 12345678`, and a numeric prefix translated after "commit" but not after "compteur".
2. **Bare "head":** fixed. The lowercase word "head" no longer counts, and `HEAD` is only recognised in capitals. The other triggers are commit(s), sha / sha-1, merge(d/s), cherry-pick(ed), revert(ed), rebase(d) and `git show|log|diff|checkout|reset|revert|rebase`. I also allowed short connecting words between the keyword and the SHA, so "HEAD is now at …" and "rebased onto …" work (they failed without it). Tests check that "at the head deadbeef" and "Head cafe123" are left alone, and that `HEAD` / "rebased onto" / "merge" / "sha-1" do tag.
3. **Line-start rule:** fixed. It now only fires on lines shaped like `git log --oneline` (hex token with a letter, a space, then text), and only when the same paragraph has at least two such lines. Hex-looking words at the start of prose lines, a single bullet, bare tokens with nothing after them, and one line per paragraph are all left alone. The true positive is a two-line bulleted log with backticks, where both commits are tagged.
4. **`role()` wording:** fixed. It now handles fixed/fixes, addressed, correctif, and corrige/corrigé/corriger; "re-review" still counts as a review. Tests cover all of these.
5. **`_read_meta` errors:** fixed. A bad meta file now raises `ValueError` with the file name and reason (for example `agent-x.meta.json:1: métadonnées JSON invalides (…)`, a read failure, or "objet JSON attendu, list trouvé").
6. **`load_published_shas` errors:** fixed. It raises `RuntimeError` when git is missing, when the path isn't a readable repo (message includes the path and git's error output), or when the repo has no commits, instead of returning an empty set. There's a test for a missing path and one for an empty `git init`.
7. **First-keyword-wins in `role()`:** not changed, as the review allows. A description like "Review-driven fix" is still classed as a review, so a manual spot check of real descriptions before publishing is still worth doing.
