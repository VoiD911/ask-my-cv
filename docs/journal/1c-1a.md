| Probe | Result |
|---|---|

- **Is `await stream.aclose()` in `finally` safe?** Yes. `_stream_llm` only waits inside the generator, so the generator has always finished by the time `finally` runs, whether it succeeded, failed or was cancelled. `aclose()` is then a no-op that never yields, so it can neither hang nor swallow the cancellation.

In production `emit` is `queue.put_nowait` on an unbounded queue, so this cannot happen today. ## Stage 2 — Findings

**What holds up:**
- **Spoofed headers in `trusted_proxy="none"`:** ignored at the app level. Three requests with different `CloudFront-Viewer-Address` and `X-Forwarded-For` values landed in one bucket: ok, blocked, blocked.
- **HMAC:** sound. The key is the secret and the IP is the message. 64 bits is enough, because without the key nobody can enumerate the IPv4 space.
- **Weak secret in prod:** couldn't get one through.
  - `VISITOR_SALT=""` is ignored, so the YAML value applies. In prod that is `change-me`, which is refused.

- **422 bodies:** for every error kind I tried, `msg` is a fixed template and neither `input`, `ctx` nor `url` appears:

- **Access logs:** `--no-access-log` is set. Uvicorn error tracebacks don't include client addresses, and spans don't carry the IP or visitor ID.

**Important — IPv6 users can bypass the per-visitor quota (`visitor.py`).** Each distinct IPv6 address gets its own bucket, and any IPv6 client controls at least a /64 of addresses. One attacker can rotate addresses and burn the global `daily_cap_usd` (0.50 $), taking the service down for everyone. Parsing without a port also collapses addresses into shared buckets:

| Header value | Result |
|---|---|
| `2001:db8::1` | `2001:db8:` |
| `::1` | `:` |
| `:` | `""` |
| `a:1, b:2` | `a:1, b` |
| `[2001:db8::1]:443` | `[2001:db8::1]` |

CloudFront always appends a port, so the parsing problems are mostly theoretical, but the /64 rotation is not. The plan's test `client_ip(...) == "2001:db8::1"` would have to change, so you need to agree to a plan change before applying this.

Fix:
```python
import ipaddress

def _normalize(raw: str) -> str | None:
    for candidate in (raw.rsplit(":", 1)[0], raw):
        try:
            addr = ipaddress.ip_address(candidate.strip().strip("[]"))
        except ValueError:
            continue
        if addr.version == 6:
            return f"{ipaddress.ip_network(f'{addr}/64', strict=False).network_address}/64"
        return str(addr)
    return None

# inside client_ip, cloudfront branch:
        if viewer and (ip := _normalize(viewer)):
            return ip
```

```python

    b = client_ip({"cloudfront-viewer-address": "2001:db8::ffff:443"}, None, "cloudfront")
```

**Minor 3 — the prod secret check fails open.** `environment` defaults to `dev`, and the Dockerfile doesn't set `ASK_ENVIRONMENT`. A deployment that forgets the variable starts with the public `change-me` salt, which undercuts the spec's promise to refuse to start in production with the default value. Behind a local sidecar or a Lambda Web Adapter, it rewrites `request.client` from `X-Forwarded-For`, bypassing the app's single rule for "none" mode.
